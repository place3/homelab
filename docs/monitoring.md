# Запуск и диагностика мониторинга

## Порядок проверки

1. `docker compose config --quiet` — Compose видит `.env` и корректные настройки.
2. `docker compose ps -a` — сервисы созданы и не перезапускаются из-за ошибок.
3. Prometheus `/targets` — три job находятся в состоянии UP.
4. Grafana — источник Prometheus healthy, дашборд загружен.
5. `python3 scripts/verify_stack.py` — все восемь запросов дашборда возвращают данные.

Стандартные локальные URL: Prometheus `http://127.0.0.1:29090/targets`,
Grafana `http://127.0.0.1:23030`. На удалённом сервере нужен SSH-туннель из README.
Экспортеры не публикуют отдельные порты на хосте; к ним обращается Prometheus внутри
Compose-сети по именам сервисов.

## Проблемы и следующие действия

| Симптом | Что проверить |
| --- | --- |
| Compose требует пароль | Запустить init_env.py или заполнить GRAFANA_ADMIN_PASSWORD в .env |
| init_env.py отказывается работать | .env уже существует; он специально не перезаписывается |
| Порт занят | Поменять порт в .env или остановить свой предыдущий экземпляр |
| Графики CPU/IO сначала пусты | Подождать минимум два сбора: scrape_interval 15s |
| node_exporter DOWN | Логи сервиса, bind-монтирования /proc, /sys и /, доступность Linux-метрик |
| cadvisor DOWN | Логи сервиса, /var/lib/docker, обычный Docker Engine и поддерживаемый хост |
| Цели UP, но панель пуста | PromQL в Prometheus, наличие нужных metric/labels, время после запуска |
| Grafana не принимает пароль из .env | Тому уже принадлежит другой пароль; .env задаёт учётную запись только при первой инициализации |
| Изменение дашборда через UI не сохраняется | Дашборд управляется JSON в Git; измените файл и дождитесь обновления provisioning |

Логи можно читать отдельно: `docker compose logs --tail=100 prometheus` или
`docker compose logs --tail=100 grafana`. Не публикуйте полную развёрнутую конфигурацию
с environment: она содержит пароль Grafana. Для обычной проверки достаточно config --quiet.

## Проверить синтаксис Prometheus

```bash
docker compose run --rm --no-deps --entrypoint /bin/promtool prometheus check config /etc/prometheus/prometheus.yml
```

Это не запускает ещё один постоянный Prometheus и не проверяет доступность целей.
Доступность проверяет verify_stack.py после запуска основного стека.

## Управление данными

`docker compose down` сохраняет тома. Это позволяет остановить и снова поднять
тот же проект без автоматического удаления истории метрик и Grafana.
Резервное копирование и проверка восстановления пока не реализованы.

CI использует уникальное имя проекта и выполняет down --volumes только для него.
Работающий homelab и его SSH-ключи CI не использует.
