# Проверка работающего стенда

Состояние зафиксировано 22 октября 2026 года. Это проверка текущего состояния, а не нагрузочное тестирование или аудит безопасности. Команды выполнялись на сервере по SSH; существующие сервисы не перезапускались и их конфигурация не менялась.

## Контейнеры

```bash
docker compose ls
docker ps -a --format 'table {{.Names}}\t{{.Status}}\t{{.Ports}}'
```

На момент проверки 10 контейнеров находились в состоянии Up, в том числе Jellyfin, cAdvisor и Pi-hole с состоянием healthy. Дополнительно были два старых остановленных тестовых контейнера; их причина остановки не исследована.

## Prometheus

```bash
curl --fail --silent http://127.0.0.1:9090/api/v1/targets
```

Из ответа API были выделены следующие поля:

| job | health | lastError |
| --- | --- | --- |
| cadvisor | up | пусто |
| node_exporter | up | пусто |
| prometheus | up | пусто |

`up` подтверждает успешный сбор с этих целей на момент проверки. Настройки алертов, полнота метрик и retention отдельно не проверялись.

## Grafana

```bash
curl --fail --silent http://127.0.0.1:3030/api/health
```

API вернул состояние базы `ok`. Порт хоста 3030 опубликован на порт 3000 контейнера. Отдельная проверка содержимого дашбордов пока не выполнена.

## Система и firewall

```bash
systemctl --failed --no-pager
free -h
df -h /
sudo ufw status verbose
```

Неисправных units не обнаружено. Корневой раздел был заполнен на 39%. UFW включён, политики по умолчанию: deny incoming, allow outgoing, deny routed.

Полный доступ к опубликованным Docker-портам нельзя оценить только по UFW: требуется учитывать правила Docker и маршрутизатора. Доступ из интернета в ходе этой проверки не тестировался. Частные адреса, ключи, пароли и локальные рабочие данные в репозиторий не включены.

## Интеграционная проверка публичного Compose

На том же Linux amd64-хосте создан отдельный временный Compose-проект со своими
именованными томами и сетью. Интерфейсы привязаны к 127.0.0.1 на 29090/23030;
существующий стек на 9090/3030 продолжал работать. Пароль тестовой Grafana сгенерирован
во временном .env, не выводился в журнал и не переносился в репозиторий.

Проверены:

- `docker compose config --quiet`.
- `promtool check config` — конфигурация Prometheus корректна.
- Запуск всех четырёх сервисов с образами из compose.yaml.
- Три scrape target в состоянии UP.
- Grafana database: ok.
- Health check автоматически созданного источника Prometheus: OK.
- Автоматически загруженный дашборд Homelab Overview.
- Непустые результаты PromQL всех восьми панелей, включая скорости CPU и дискового I/O.

Итог verify_stack.py:

```json
{
  "targets_up": 3,
  "grafana_database": "ok",
  "datasource": "healthy",
  "panels_with_data": 8
}
```

После проверки удалены только временный проект, его два тома и временные файлы.
У существующего Prometheus повторно проверены три UP-цели, у Grafana — database ok.

GitHub Actions выполняет аналогичную проверку в отдельном Ubuntu runner. Это не
проверка восстановления, нагрузки, доставки алертов или развёртывания на домашний сервер.
